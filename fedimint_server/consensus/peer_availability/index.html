Module peer_availability 

Source
Expand description

This guardian’s view of its peers’ availability.

A peer counts as available in a 1-minute slot if it sent us any AlephBFT message in it. Every running peer sends consensus traffic while the federation is active, including a slow one that lags behind and still runs an older session, while an offline or frozen peer, or one whose consensus is stuck, sends nothing. A slot in which we heard from fewer than threshold - 1 peers means the federation was idle, or we were down or cut off ourselves, so it does not count.

PeerActivity counts slots in memory; persist_peer_availability folds them every 10 minutes into exponential moving averages with the time constants in PEER_AVAILABILITY_WINDOWS_SECS, persisted as PeerAvailabilityState.
